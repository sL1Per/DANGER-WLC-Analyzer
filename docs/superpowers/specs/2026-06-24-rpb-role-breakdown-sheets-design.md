# RPB Role Breakdown sub-tabs — design

**Date:** 2026-06-24
**Status:** Approved (brainstorming)

## Goal

Rebuild the exported RPB workbook's per-role sheets as nested sub-tabs inside the
web app's existing **Role Breakdown** tab. The reference export is
`RPB for ssc _ tk … in Serpentshrine Cavern (only bosses) (no wipes).xlsx`,
generated by the original Shariva RPB Google-Sheets tool via "export roles".

The workbook's `General` sheet is **out of scope** — its content already lives in
the Consumables / Summary pages. Every other sheet is implemented:

- `Tank`, `Healer`, `Caster`, `Physical` — the **role sheets**.
- `Tank - casts`, `Healer - casts`, `Caster - casts`, `Physical - casts` — the
  **casts sheets**.

## Decisions (locked during brainstorming)

1. **Full faithful replication** — including the hit-type "Stats & Misc" section
   and "Trinkets & Racials", which require data the API does not fetch today.
2. **Keep the existing summary as a 9th sub-tab** — an `Overview` sub-tab (today's
   cross-role `SummaryView`) comes first, then the 8 Excel-matching sub-tabs.
3. **Players as rows** (not the Excel's players-as-columns). Casts sheets render
   **one sub-table per class** (rows = that class's players, columns = that
   class's abilities) so columns stay dense despite differing class abilities.
4. **Hybrid data sourcing (approach C)** — the WCL `table` API supplies the
   hit-type Stats + Trinkets/Racials (server-aggregated → **BOSSES-only**); the
   existing event model supplies casts / activity / cooldowns / avoidable, keeping
   the report-fights scoping invariant for those.

## Scope & behavior

- **9 sub-tabs** under Role Breakdown: `Overview`, `Tank`, `Tank - Casts`,
  `Healer`, `Healer - Casts`, `Caster`, `Caster - Casts`, `Physical`,
  `Physical - Casts`.
- The **8 Excel sub-tabs are BOSSES-only**: their hit-type/trinket data is
  aggregated server-side over boss fights and cannot be re-scoped client-side. On
  a single-pull card or the TRASH card, the sub-nav shows **only `Overview`**,
  preserving today's behavior. On the combined BOSSES card, all 9 appear.
- Sub-tab selection is held in a URL param (`sub=`), mirroring `cat=` today.

This BOSSES-only gating is consistent with how Rankings and Buff-consumables
already gate (`BOSSES_ONLY_CATS` in `ReportPage`). It is a deliberate divergence
from the event-scoping invariant for the hit-type sections only — those sections
are sourced from pre-aggregated tables, not from `report.fights` events.

## Sheet content reference (from the export)

### Role sheets (`Tank` / `Healer` / `Caster` / `Physical`)
One player per column in the Excel; we render players as rows. Sections:

- **Stats and Miscellaneous** — Battle Shout uptime%, Commanding Shout uptime%,
  Critical heals done, outgoing {Critical, Dodge, Miss, Parry, Resist}, incoming
  melee {Critical, Crushing Blow, Blocked, Dodge, Immune, Miss, Parry},
  `# of extra Windfury Attacks`, `# of Battle Squawk buffs on bosses`. Each
  count is shown as `N (pct%)` exactly as the sheet does (raw count + share).
- **Trinkets and Racials** — named on-use trinkets/racials with use counts
  (e.g. Icon of the Silver Crescent, Badge of Tenacity, Bloodlust Brooch,
  Berserking, Blood Fury, Fear Ward).
- **Raw avoidable damage taken by tracked abilities** — per tracked ability the
  damage amount; plus `Damage reflected`, `Damage to hostile players
  (counts as done to self)`, `Friendly Fire …`, `# of deaths in total`,
  `Total (partly) avoidable damage taken` (+ the relative bar row).
- **Avoidable debuffs applied by tracked abilities** — per tracked debuff the
  count of applications (e.g. Nether Vapor, Silence (Thaladred the Darkener)).

### Casts sheets (`… - casts`)
Grouped by class. Sections:

- **# of single target casts** — every class ability with its cast count. Some
  rows carry annotations: debuff/buff abilities show `(uptime% - overall: N%)`
  and a per-player `(N%)`; heals show `(overheal%)`; rank-grouped heals appear as
  separate rows (e.g. `Healing Touch (rank 13)`, `(rank 7-12)`, `(rank 1-6)`).
  `Melee - excluded from activity` is its own row.
- **# of aoe casts** — aoe abilities (e.g. Consecration, Hurricane, Swipe).
- **Activity rows** — `seconds active on single target`,
  `relative active % on single target`, `relative active % total`,
  `relative active % on aoe`, `seconds active on aoe`,
  `active % overall from WarcraftLogs (trash %)`.
- **Class specific cooldowns** — per cooldown ability a triple
  `… on trash` / `… on bosses` / `… total` (some are
  `used or gained* on …`). On a BOSSES-only export the trash column is 0.

## Architecture

### Data layer (`apps/api`)

- **Probe first.** Add `scripts/probe-rpb-tables.ts` (following the existing
  `scripts/probe*.ts` pattern) to dump the v2 `table` JSON for `DamageDone`,
  `DamageTaken`, `Casts`, `Buffs` on a real boss fight, confirming the exact field
  names for hit-type counts (crit/dodge/parry/miss/resist/crushing/block/immune)
  and on-use cast counts before normalization is written.
- **New query.** `fetchTable(code, accessToken, dataType, fightIds)` in `wcl.ts`
  using `reportData.report.table(dataType:, fightIDs:, hostilityType: Friendlies)`.
  Fetched once over the report's boss-fight ids.
- **New normalized `ReportData` fields** (all optional; absence drives the
  existing "refresh from WCL" notice on stale caches):
  - `hitStats?: PlayerHitStats[]` — per player:
    `outgoing: { crit, dodge, miss, parry, resist }`,
    `incomingMelee: { crit, crushing, blocked, dodge, immune, miss, parry }`,
    `critHeals`, `extraWindfury`, `battleSquawk` — each value a
    `{ count: number; pct: number }`.
  - `trinketUses?: TrinketUse[]` — `{ playerId, name, count }`, produced by
    matching a curated trinket/racial spellId list against the Casts/Buffs table.

### Reference data (`packages/data`)

- **`classAbilityCatalog.ts`** — the primary authoring effort. Full per-class
  ability catalog: `{ className, key, name, category: 'single'|'aoe'|'cooldown'|'heal',
  spellIds, ranks?, uptimeAnnotated?, role?, tracked? }`. Drives the casts tab's
  complete listing, including 0-cast rows, exactly like the sheet. The existing
  curated severity-tracked `classAbilities` is folded in as the `tracked` flag —
  no duplicate source of truth.
- **`trinketRacials.ts`** — curated on-use trinket/racial `spellId → display name`.
- **Avoidable debuffs** — extend the existing `avoidableAbilities.ts` with the
  tracked avoidable-debuff spellIds (Nether Vapor, Silence (Thaladred), …) used by
  the role sheet's "Avoidable debuffs applied" section.

### Core analyses (`packages/core`)

New module `rpbSheets.ts` with two pure builders:

- `roleSheet(report, role, cfg)` → per-player rows containing the four role-sheet
  sections. Reuses `rpb()` row data for deaths / friendly fire / reflected / PvP /
  absorbed / avoidable-damage-by-ability, and adds the new `hitStats` (Stats) and
  `trinketUses` (Trinkets) sections plus avoidable-debuffs-applied counts from
  `enemyDebuffs` resolved to names via `masterData.abilities`.
- `roleCasts(report, role, cfg)` → grouped by class. Per class: catalog ability
  rows × players (single/aoe cast counts from `playerCasts`, uptime/overheal
  annotations, rank flags), plus activity rows (`activity()`), plus cooldown rows
  (on-boss counts; the on-trash/total fields exist in the model and render 0 on a
  BOSSES-only view). Client-side scoped from events → keeps the report-fights
  invariant for this builder.

Names for casts/debuffs/trinkets resolve from the already-fetched
`masterData.abilities` (`gameID → name`), exposed today as `abilityMeta`.

### Web UI (`apps/web`)

- **`RoleBreakdownView`** — owns the sub-nav and the `sub=` URL param; renders
  `Overview` (today's `SummaryView`, unchanged) or one role/casts table. Replaces
  the direct `SummaryView` render in `ReportPage`'s `roles` case. The sub-tab list
  is dynamic: BOSSES card → all 9; other cards → only `Overview`.
- **`RoleSheetTable`** — players as rows; the four sections render as grouped
  column bands (Stats / Trinkets / Avoidable / Debuffs). Severity coloring via the
  existing heatmap/`sev-*` helpers (per the severity-color convention).
- **`RoleCastsTable`** — one sub-table per class (rows = that class's players,
  columns = that class's catalog abilities), followed by activity and cooldown
  sub-tables.

## Error handling & edge cases

- **Stale caches** — reports cached before this feature lack `hitStats` /
  `trinketUses`; the role sheets show the existing "Refresh from WCL" notice for
  those sections, consistent with current RPB behavior.
- **Kalecgos** — already excluded upstream from RPB aggregation; unchanged.
- **Missing combatantInfo on some T6 fights** — already a known caveat; hit-type
  data comes from the table API independent of combatantInfo, so it is unaffected.
- **Classes absent from a role** — `roleCasts` only emits class sub-tables for
  classes actually present in the role.

## Testing (TDD per project norm)

- **API / normalize** — fixture-driven: table JSON → `hitStats` / `trinketUses`.
- **Core** — `roleSheet` / `roleCasts` against a small synthetic `ReportData`:
  catalog grouping, single/aoe cast counts, activity, cooldown split, hit-stat and
  trinket passthrough, BOSSES scoping, name resolution.
- **Web** — 9 sub-tabs on the BOSSES card vs. only `Overview` elsewhere;
  players-as-rows render; class sub-tables only for present classes.

## Implementation phases (for the plan)

1. **API**: probe `table` shapes, add `fetchTable`, normalize `hitStats` /
   `trinketUses` into `ReportData` (+ tests).
2. **Data**: `classAbilityCatalog.ts`, `trinketRacials.ts`, avoidable-debuff
   extensions (+ tests).
3. **Core**: `roleSheet` + `roleCasts` builders (+ tests).
4. **Web**: `RoleBreakdownView` + `RoleSheetTable` + `RoleCastsTable` (+ tests).

## Out of scope

- The `General` sheet (already covered by Consumables / Summary).
- Trash-scoped hit-type data (BOSSES-only by the approach-C decision).
- Mobile-responsive polish of the new tables (tracked separately in TODO.md).
